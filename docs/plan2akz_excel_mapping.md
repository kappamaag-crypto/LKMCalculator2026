# plan2akz — Excel Mapping Specification

Источник: рабочий файл `КалькуляторЭКСЕЛЛЬ.xlsx`.

## 1. Фактическая структура шаблона

- Лист: `База`.
- Размер: 25 строк × 21 колонка.
- Основной рабочий диапазон: `B:R`.
- Есть две секции расчёта:
  1. `B1:R11` — вариант «Если стоимость в КГ».
  2. `B15:R25` — вариант «Если стоимость в литрах».
- В каждой секции предусмотрено 2 слоя + отдельные строки разбавителей + итог.
- Формулы Excel уже существуют в шаблоне; v3 не должен использовать их как второй расчётный движок.
- Скрытых строк/колонок нет.
- Лист не имеет заданной `print_area`; ориентация portrait.

## 3. Разбавитель

Для каждой секции есть две legacy-строки разбавителя. В v3 они должны заполняться только если в `CalculationResult` реально есть соответствующий разбавитель.

Не использовать текстовые названия `Разбавитель для грунта`/`Растовритель для эмали` как источник расчёта. Это только legacy-представление.

## 4. Итоги

| CalculationResult | Excel |
|---|---|
| `result.total_dft` | `I[total_row]` |
| `result.total_theoretical_consumption_kg` | `P[total_row]` |
| `result.total_practical_consumption_kg` | `Q[total_row]` |
| `result.total_cost_per_m2` | `R[total_row]` |
| теоретический/практический расход в литрах | отдельные поля/строки должны быть добавлены только при необходимости, не через пересчёт Excel |

## 5. Важное ограничение legacy-шаблона

Шаблон физически рассчитан на 2 слоя и 2 строки разбавителя. Поэтому нельзя просто записывать систему из 3+ слоёв поверх него без изменения структуры.

Правильное решение для v3:

1. сохранить `База` как legacy customer-facing форму;
2. сделать адаптер, который умеет динамически расширять строки с сохранением стилей и merged cells;
3. не переносить формулы расчёта из v3 в Excel;
4. значения из `CalculationResult` записывать как значения;
5. при системе >2 слоёв расширять таблицу, а не отбрасывать слои;
6. после расширения пересчитывать только отображаемые итоги из `CalculationResult`, а не Excel formulas.

## 6. Режимы отчёта

### Engineering
Показывать:
- площадь;
- систему;
- материалы;
- DFT/WFT;
- теоретический/практический расход;
- разбавитель;
- стоимость системы руб/м².

Не показывать складские/закупочные данные.

### Commercial
Показывать:
- цены;
- практический расход;
- количество на объект;
- стоимость м²;
- стоимость объекта;
- разбавитель и его стоимость.

### Full
Показывать объединённый набор.

## 7. Обнаруженные проблемы текущего CustomerExcelExporter

Текущий адаптер умеет находить отдельные подписи и добавлять отдельный лист `Расчёт`, но это не является заполнением legacy-таблицы `База`.

Следующая реализация должна заменить этот подход на прямое заполнение `База`, сохранив исходное оформление.

## 8. Контрольный golden case

Для первого теста использовать существующую структуру из шаблона:
- площадь: 270 м²;
- слой 1: Грунт-Эмаль Blank Universal, DFT 110 мкм;
- слой 2: Эмаль Blank Finish, DFT 60 мкм;
- потери: 0%;
- разбавитель: 5% для каждого слоя.

Контрольные значения сравниваются между v3 `CalculationResult` и Excel. Формулы Excel из исходного файла используются только как исторический reference для проверки, но не как источник истины.
