# plan2akz — основной план развития АКЗ-калькулятора v3

> **Живой план проекта.** После каждого существенного этапа статусы обновляются прямо здесь.
>
> **Главный приоритет продукта:** **расчёт АКЗ → система покрытия → сравнение → Excel/PDF**.
>
> **Ключевое требование:** система покрытия должна поддерживать **2, 3, 4 и любое разумное количество слоёв**. Ограничение старого Excel-шаблона на 2 слоя не является ограничением калькулятора v3.
>
> Все дополнительные функции развиваются вокруг этого workflow и не должны его ломать.

## 0. Правила

Статусы:
- **[НЕ ВЫПОЛНЕНО]** — ещё не реализовано.
- **[ЧАСТИЧНО]** — реализована только часть.
- **[ВЫПОЛНЕНО, НО НУЖНО...]** — основная часть готова, есть конкретный остаток.
- **[ВЫПОЛНЕНО]** — реализовано и проверено.
- **[ЗАБЛОКИРОВАНО]** — нужен другой этап/решение.
- **[ОТЛОЖЕНО]** — сознательно перенесено.

Для каждого изменения:
1. не ломать рабочий АКЗ-расчёт;
2. расчётная логика остаётся в Domain/Service, не в UI;
3. Excel не становится вторым расчётным движком;
4. PDF и Excel получают данные из одного `CalculationResult`;
5. инженерные и складские данные не смешиваются без необходимости;
6. тест/smoke-check;
7. отдельный commit;
8. после commit обновляется `plan2akz.md`.

# I. ОСНОВНОЙ WORKFLOW АКЗ — КРИТИЧЕСКИЙ ПРИОРИТЕТ

## 1. Расчёт АКЗ

**[ВЫПОЛНЕНО, НО НУЖНО ПРОДОЛЖИТЬ]**

Уже есть: расчёт слоёв, DFT/WFT, теоретический/практический расход, кг/м² и л/м², разбавитель, стоимость системы, площадь и итоги, `CalculationResult`, несколько баз разбавления, валидация и отсутствие промежуточного округления в основном движке.

Осталось: precision/regression tests, полный контроль единиц, стабильный 2К pipeline, технологические проверки и прозрачный источник инженерных результатов.

**Обязательное требование:** расчёт должен работать не только для 2 слоёв, а для **3+ слоёв без потери точности и данных**.

## 2. Система покрытия на основном экране

**[ЧАСТИЧНО]**

Целевой workflow: `Расчёт → сформировать/получить систему → проверить → сравнить → экспортировать`.

Система должна быть **динамической по количеству слоёв**: минимум 2, 3, 4 и далее без архитектурного ограничения вида `layer1/layer2`.

Осталось:
- полноценная модель/UX системы;
- add/remove/reorder слоёв;
- 2+ слоя в одном расчёте;
- save/load/copy system с сохранением всех слоёв и их порядка;
- удобное получение системы из расчёта;
- one-click добавление результата в сравнение;
- минимизация переходов в БД;
- запрет silent truncation при любом количестве слоёв.

## 3. Материал из экрана расчёта

**[ВЫПОЛНЕНО, НО НУЖНО ДОПРОВЕРИТЬ]**

Сделано: `+ Материал` из расчёта, запись в БД, автоматическое добавление слоем в текущий расчёт, обновление каталогов, duplicate check по нормализованному имени и добавление существующего материала при дубле с информационным предупреждением.

Осталось: regression test duplicate normalization, проверка всех полей, перезапуск/сохранность, проверка систем, сравнения и экспорта.

## 4. Сравнение систем АКЗ

**[ВЫПОЛНЕНО, НО ПОКА НУЖНО РАСШИРИТЬ]**

Есть базовое сравнение и инженерный приоритет над ценой.

Осталось:
- корректное сравнение систем из 2, 3, 4+ слоёв;
- 2К;
- технологические показатели;
- объяснение различий;
- UX добавления результата из расчёта;
- regression tests;
- проверка, что система не обрезается до двух слоёв.

# II. EXCEL / PDF — ОСНОВНОЙ ВНЕШНИЙ РЕЗУЛЬТАТ

## 5. Excel — рабочий customer-facing экспорт

**[ВЫПОЛНЕНО, НО НУЖНО ДОПРОВЕРИТЬ]**

`КалькуляторЭКСЕЛЛЬ.xlsx` признан **реальным рабочим документом**, а не обычным шаблоном. Произвольный лист `Расчёт` не может считаться заменой.

**Важно:** ограничение исходного `База` на 2 слоя относится только к историческому оформлению Excel. Экспорт v3 обязан поддерживать **2, 3, 4 и более слоёв** и не имеет права молча отбрасывать слои.

### 5.1. Аудит рабочего Excel

**[ВЫПОЛНЕНО]**

Проверен файл `КалькуляторЭКСЕЛЛЬ.xlsx`.

Фактическая структура:
- 1 лист: `База`;
- 25 строк × 21 колонка;
- основной диапазон `B:R`;
- две секции: `B1:R11` — стоимость в кг; `B15:R25` — стоимость в литрах;
- каждая секция исторически рассчитана на 2 слоя + 2 строки разбавителя + итог;
- имеются merged cells;
- формулы находятся непосредственно в старом документе;
- скрытых строк/колонок нет;
- print area не задана; portrait;
- исходный файл содержит полноценное форматирование, числовые форматы и клиентскую форму.

**Критический вывод:** Excel нельзя просто дополнять отдельным листом и считать задачу выполненной. Нужно заполнять существующую `База`, сохраняя её визуальную форму, и при этом уметь динамически расширять её для 3+ слоёв.

### 5.2. Excel Mapping Specification

**[ВЫПОЛНЕНО]**

Создан документ `docs/plan2akz_excel_mapping.md`.

Зафиксирована карта `CalculationResult → лист/ячейка → единица/формат → правило заполнения`, включая поля B:R, итоги, строки разбавителя, kg/l секции, Engineering/Commercial/Full и ограничение legacy-шаблона на 2 слоя.

Зафиксировано обязательное правило: Excel получает значения из `CalculationResult`, а не пересчитывает их.

Стратегия v3 реализована: `База` расширяется строками слоёв и разбавителей, исходные merged cells восстанавливаются после вставки, итоговые строки сдвигаются вниз, оба блока kg/l остаются синхронными.

Commit документа: `2851063adc2412a218dc6a997514dd2f662cbdbe`.

### 5.3. Multi-layer Excel Exporter

**[ВЫПОЛНЕНО, НО НУЖНО ПРОДОЛЖИТЬ ПРОВЕРКУ]**

Реализовано в `CustomerExcelExporter`:
- прямое заполнение реального листа `База`;
- поддержка 2, 3, 4+ слоёв через динамическое расширение;
- отдельные строки разбавителя для каждого слоя;
- перенос итоговых строк вниз без потери данных;
- восстановление merged cells после `insert_rows()`;
- копирование стилей, границ, форматов и высоты строк для добавленных строк;
- оба legacy-варианта kg/l;
- значения берутся из `CalculationResult`, а Excel не используется как расчётный движок;
- Engineering не выводит цены материалов/разбавителей, но сохраняет итоговую стоимость системы руб/м²;
- Commercial/Full выводят ценовые поля;
- при 3+ слоях данные не обрезаются и не создаётся отдельный лист `Расчёт` как замена `База`.

Последний исправляющий commit exporter: `285e324ee177497a1b5b0181d1f72fbcb223e311`.

### 5.4. Проверка Excel

**[ЧАСТИЧНО]**

Добавлены regression tests для customer-facing `База`:
- 2 слоя;
- 3 слоя;
- 4 слоя;
- проверка сдвига второго kg/l блока;
- проверка итоговых строк;
- проверка сохранения стилей;
- проверка отсутствия silent truncation.

Также добавлены regression tests инженерного сравнения Excel для 2/4/5 слоёв и проверки отсутствия truncation.

Последний CI до исправлений показал `168 passed / 4 failed / 13 warnings`. Причины были локализованы: неправильный вызов `_cell()` в новой таблице сравнения и потеря заливки внутренних ячеек merged ranges при расширении customer-facing шаблона.

Исправления:
- `_sheet_comparison()` теперь передаёт колонку `1` и значение отдельно, без передачи текста показателя в аргумент `col`;
- `CustomerExcelExporter` восстанавливает заливку внутренних ячеек после `unmerge_cells()/merge_cells()`;
- исправления зафиксированы отдельными commit-ами.

**Текущий статус:** код исправлен, но этап не закрывается до зелёного CI.

Осталось:
- дождаться/проверить полный pytest suite после исправлений;
- golden case с несколькими реальными разбавителями;
- длинные реальные названия материалов;
- все режимы Engineering/Commercial/Full;
- проверка Excel/LibreOffice;
- печать/PDF conversion;
- визуальная проверка исходного клиентского оформления.

## 6. PDF — клиентский экспорт

**[ВЫПОЛНЕНО, НО НУЖНО ПРОВЕРИТЬ]**

Осталось:

- **2, 3, 4+ слоя**;
- длинные названия;

# III. РАСЧЁТНЫЙ ДВИЖОК

## 7. Точность / единицы / regression

**[ЧАСТИЧНО]**

Нужно: DFT/WFT tests, dilution tests, theoretical/practical consumption, cost, area, systems, **multi-layer golden tests (2/3/4+)**, отсутствие промежуточного округления и единый контроль единиц.

## 8. 2К материалы

**[НЕ ВЫПОЛНЕНО]**

Использовать существующие `MaterialComponent`, `MaterialMix`, `Package`. Результат отдельно показывает A/B, соотношение, потребность, комплекты и стоимость. Не превращать приложение в ERP.

2К должен корректно работать как один или несколько компонентов внутри любого слоя и не ломать multi-layer pipeline.

## 9. Фасовка / закупка

**[НЕ ВЫПОЛНЕНО]**

Отдельный коммерческий слой: фасовка, количество банок/комплектов, остаток, резерв, закупочная стоимость. Инженерный расчёт не должен зависеть от склада.
