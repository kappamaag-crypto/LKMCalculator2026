# plan2akz — основной план развития АКЗ-калькулятора v3

> **Живой план проекта.** После каждого существенного этапа статусы обновляются прямо здесь.
>
> **Главный приоритет:** **расчёт АКЗ → система покрытия → сравнение → Excel/PDF**.
>
> Ключевое требование: система покрытия поддерживает 2, 3, 4 и любое разумное количество слоёв. Legacy Excel на 2 слоя не является ограничением калькулятора v3.

## 0. Правила

1. Не ломать рабочий АКЗ-расчёт.
2. Расчётная логика остаётся в Domain/Service, не в UI.
3. Excel не становится вторым расчётным движком.
4. PDF и Excel получают данные из одного `CalculationResult`.
5. Инженерные и складские данные не смешиваются без необходимости.
6. Каждый существенный этап покрывается тестом/smoke-check.
7. Отдельный commit.
8. После commit обновляется этот план.

---

# I. ОСНОВНОЙ WORKFLOW АКЗ — КРИТИЧЕСКИЙ ПРИОРИТЕТ

## 1. Расчёт АКЗ

**[ВЫПОЛНЕНО, НО НУЖНО ПРОДОЛЖИТЬ]**

Есть расчёт слоёв, DFT/WFT, теоретический/практический расход, кг/м² и л/м², разбавитель, стоимость, площадь, `CalculationResult`, валидация и multi-layer расчёт.

Добавлен отдельный precision/regression этап: формулы проверяются на отсутствие промежуточного округления, согласованность кг/л, масштабирование на площадь и разные основания разбавления.

Осталось: полный контроль единиц на уровне всех входных моделей, технологические проверки и финальная визуальная проверка 2К pipeline.

## 2. Система покрытия на основном экране

**[ЧАСТИЧНО]**

Целевой workflow: `Расчёт → система → проверка → сравнение → экспорт`.

Система должна быть динамической по числу слоёв без архитектурного ограничения `layer1/layer2`.

Осталось: полноценная UX-модель системы, add/remove/reorder, save/load/copy, удобное получение системы из расчёта и визуальный smoke-check сквозного workflow.

## 3. Материал из экрана расчёта

**[ВЫПОЛНЕНО, НО НУЖНО ДОПРОВЕРИТЬ]**

`+ Материал`, запись в БД, добавление слоем в текущий расчёт, обновление каталогов и duplicate check реализованы.

Осталось: regression duplicate normalization, проверка всех полей и сохранности после перезапуска.

## 4. Сравнение систем АКЗ

**[ВЫПОЛНЕНО, НО ПОКА НУЖНО РАСШИРИТЬ]**

Сравнение `CalculationResult` выполняется без повторного расчёта. Сохраняются 2/3/4+ слоёв. Исправлен двойной счёт разбавителя; отдельно показываются ЛКМ, разбавитель и итог. Comparison Excel соответствует основным показателям UI и поддерживает динамические слои. `compare_results()` блокирует смешение разных площадей. UI передаёт результат расчёта напрямую в `ComparisonView`.

2К также покрыт в сравнении: он остаётся одним слоем, а стоимость ЛКМ + разбавителя не удваивается.

Осталось: технологические показатели, объяснение различий и визуальная проверка UI.

# II. EXCEL / PDF — ОСНОВНОЙ ВНЕШНИЙ РЕЗУЛЬТАТ

## 5. Excel — рабочий customer-facing экспорт

**[ВЫПОЛНЕНО, НО НУЖНО ДОПРОВЕРИТЬ]**

Customer-facing экспорт использует реальный лист `База`, одну таблицу и динамическое расширение для 2/3/4+ слоёв. Исторический второй kg/l блок не переносится.

### 5.1. Аудит рабочего Excel

**[ВЫПОЛНЕНО]**

Проверен `КалькуляторЭКСЕЛЛЬ.xlsx`: лист `База`, диапазон B:R, merged cells, исторические 2-слойные секции, клиентское форматирование.

### 5.2. Excel Mapping Specification

**[ВЫПОЛНЕНО]**

Создан `docs/plan2akz_excel_mapping.md`. Зафиксировано правило: Excel получает значения из `CalculationResult` и не пересчитывает их.

### 5.3. Multi-layer Excel Exporter

**[ВЫПОЛНЕНО, НО НУЖНО ПРОДОЛЖИТЬ ПРОВЕРКУ]**

Реализованы один customer-facing блок, 2/3/4+ слоя, строки разбавителя, перенос итогов, восстановление merged cells и стилей, Commercial/Full и отдельный Engineering exporter.

Engineering Excel: один лист `Инженерный расчёт`, две таблицы — состав/расчёт и итог системы. Складские/закупочные поля не выводятся.

### 5.4. Проверка Excel

**[ЧАСТИЧНО]**

Regression покрывает 2/3/4 слоя, смешанные разбавители, длинные названия, цены Commercial/Full, Engineering export, print area/fit-to-page и comparison 4/5 слоёв.

2К покрыт в customer-facing Excel и Engineering Excel: 2К выводится ровно один раз как один слой, A/B-компоненты и ERP-закупочные поля не выводятся.

Осталось: визуальная проверка клиентского оформления, реальная печать/PDF conversion и финальная проверка отсутствующих цен.

## 6. PDF — клиентский экспорт

**[ВЫПОЛНЕНО, НО НУЖНО ПРОВЕРИТЬ]**

PDF строится из `SystemCalculationResult`, поддерживает 2/3/4+ слоёв, comparison, длинные названия и неизвестную стоимость.

2К покрыт regression-тестом: 2К остаётся одним слоем и компоненты A/B не становятся отдельными расчётными позициями.

Осталось: визуальная проверка всех режимов, печати и совпадения состава Excel ↔ PDF.

# III. РАСЧЁТНЫЙ ДВИЖОК

## 7. Точность / единицы / regression

**[ЧАСТИЧНО — СЕРВИСНЫЙ ЭТАП ДОБАВЛЕН]**

Добавлены проверки:
- отсутствие промежуточного округления при последовательном расчёте WFT → расход → кг;
- инвариант `кг/м² = л/м² × плотность` для теоретического и практического расхода;
- сохранение удельного расхода при масштабировании на площадь;
- согласованность WFT для разных оснований разбавления (по объёму ЛКМ, объёму смеси и массе);
- существующие проверки DFT/WFT, theoretical/practical consumption, cost и dilution сохранены.

Новый commit: `8598365345d000c884978642cde4e916c0fbf7a0` — `test: strengthen precision and unit invariants`.

Затем добавлен сервисный regression-этап: commit `874002fca9aff4713b6a0215d1625087a924167a` — `test: add system calculation precision invariants`.
Он проверяет `CalculationService`/`SystemCalculationResult` на системных golden-кейсах 2/3/4/5 слоёв: точную сумму DFT, теоретического и практического расхода, стоимости и разбавителя, линейность площади и отсутствие промежуточного округления.

CI для предыдущего precision-коммита `34439245472` — **success**. CI для обновления `docs/plan2akz.md` `34439280625` — **success**.

Осталось:
- проверить новый service-level regression в CI;
- системно проверить единицы входов/выходов во всех слоях, разбавителях и экспортерах;
- исключить скрытые преобразования/округление в UI/export;
- добавить/проверить независимые golden cases для экспортных границ;
- затем закрыть §7.

## 8. 2К материалы

**[ЧАСТИЧНО — PIPELINE ПОКРЫТ, ОСТАЛИСЬ ЕДИНИЦЫ/ТЕХНОЛОГИЯ]**

Базовый принцип: 2К-материал — **один готовый материал/один слой**, а не две расчётные позиции.

Подтверждено:
- `is_two_component=True` проходит `CalculationService` как один слой;
- 2К работает в системах 2/3/4/5 слоёв;
- 2К работает первым, средним и последним слоем;
- положительный физический расход сохраняется в кг/м² и л/м²;
- `MaterialMix` и компоненты A/B восстанавливаются из SQLite;
- `is_two_component` сохраняется ORM → Domain;
- 2К проходит `ComparisonEngine.compare_results()` как один слой;
- comparison не удваивает стоимость разбавителя;
- customer-facing Excel выводит 2К один раз и не выводит A/B закупочные данные;
- Engineering Excel выводит 2К один раз и не выводит A/B закупочные данные;
- PDF принимает 2К как один слой.

Последние commits 2К pipeline: `2e5fc6a`, `1bc83e1`, `0fdeb25`, `db01a7e`, `7878dd0`.

CI базового multilayer 2К этапа `34437813196` — success. Полный export-stage CI запускался после PDF commit; его состояние требуется финально подтвердить.

Осталось:
- финально подтвердить зелёный CI полного export pipeline;
- проверить правила единиц готового mixed material;
- при необходимости добавить pot life/induction time validation.

**Не требуется:** отдельный расчёт количества A/B, отдельная стоимость A/B, комплектность закупки или ERP-логика.

## 9. Фасовка / закупка

**[НЕ ВЫПОЛНЕНО]**

Отдельный коммерческий слой: фасовка, количество банок/комплектов, остаток, резерв, закупочная стоимость. Инженерный расчёт от склада не зависит.

**[ЧАСТИЧНО]**

## 11. История / snapshots

**[ЧАСТИЧНО]**

`CalculationSnapshot` должен сохранять полный список слоёв, порядок, входы, результаты, версию формул/приложения и время.

## 11.1. Автоматическая синхронизация истории и БД материалов

**[НЕ ВЫПОЛНЕНО]**
